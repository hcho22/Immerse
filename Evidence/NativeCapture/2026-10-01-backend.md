## Implementation and Behavior

`Packages/NativeAdapters/Sources/NativeAdapters/AVFoundationCaptureBackend.swift` contains the iOS-only AVCaptureSession backend, on a dedicated serial actor executor. It creates only a video device input, disables automatic application audio-session configuration, and never requests microphone authorization. `CaptureStartupCoordinator` remains responsible for configurable camera permission handling; the backend itself requires prior authorization and prompts for nothing.

Photo data is collected by the processing delegate and handed off only after the final capture callback. Movie completion validates the actual saved file, including potentially recoverable output after an interruption. `CapturedMediaFiles` verifies photo decoding and decodes Movie frames through EOF with AVAssetReader, rejects audio tracks/invalid or over-budget files, synchronizes staged files, and does not remove them before a successful persistence acknowledgement.

`CaptureOperationCoordinator` prevents another capture or lens switch while capture, recording, validation, or persistence is pending. It retains the same file/event after a persistence failure. Explicit retry is available; an interruption ends recording and never starts another clip. Runtime errors and application deactivation suspend capture. Interruption-ended notification does not itself restart the session or recording.

The preview helper supports a mirrored front viewfinder. Photo and Movie output connections disable automatic mirroring and use unmirrored output. Each capture receives its current orientation; each Movie clip locks that orientation when recording starts. Final Movie presentation orientation remains a separate Film property. The future UI must update preview presentation after lens/orientation changes; UI wiring is not present.

`CapturePipelineReceiver` is the actor conforming to `CaptureSaveCommitting`. It owns the existing repository/pipeline and returns success only after the source and Film debit commit. Repeated delivery of the same staged URL to that receiver is idempotent within its lifetime. Movie durations use finite positive `TimeInterval` values throughout the event/domain/storage path, preserving fractions from actual AVAsset duration instead of rounding to whole seconds. The Camera budgets remain 200 and 165 seconds.

Additional unfinished safety work: receiver URL deduplication is in memory, not a durable capture receipt across process termination. Staged native files are retained on failure but are not yet in a durable per-Film retry journal or integrated with Delete Film/Discard tombstones. The existing repository Development helpers are bookkeeping, not a renderer or a verified complete-development gate. Deletion/reassembly requires crash-safe tombstones and stale-writer suppression; successful synchronous deletion tests do not establish those properties. These are implementation gaps, not captain decisions, and must be closed below the UI before acceptance.

The current file pipeline loads a source into Data, and Movie validation decodes every frame. Full-length hardware memory, latency and background-suspension evidence remain absent. No ARC-08 or ARC-10 performance/fidelity claim is made. Source capture session presets do not approve DEC-04 developed-output specifications.
