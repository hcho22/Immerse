- `sh Scripts/validate-local.sh` runs all package tests, ZIP comparison and unsigned simulator/device builds. Separate optional simulator IDs run navigation and local StoreKit tests. CI (`.github/workflows/native.yml`) runs the same script as four parts side by side (`IMMERSE_VALIDATE_PART`: packages, harness, ui-text, ui-flows; 75 minutes each) behind the one summary check `local-native`, and a pull request that changes only Markdown runs packages alone (`Scripts/validation-scope.sh`). `Scripts/validation-parts.sh` says what each part holds: list a new package, probe, test target or named suite there, or `Scripts/verify-validation-parts.sh` fails. Never interpret prepared CI or compile-only evidence as a runtime pass.
- When a tap in a screen test does nothing (the next screen never appears and the screen stays as it was), read the simulator's log before the app or the test. `backboardd`'s "didn't see a previous touch down or range-in event ...; skipping event", usually after "*** unknown digitizer", means the simulator dropped that touch (`Evidence/NativeApp/dropped-touch-059.md`); `python3 Scripts/dropped-touch-tests.py <bundle> --archive <the system.logarchive in the bundle's exported diagnostics>` reads a CI bundle for it. `Scripts/screen-tests.sh` reruns a failed screen test once, alone, only on that record inside the test's own time window (the captain, 2026-10-13). Never add a second tap, a blanket retry or Xcode's retry flags, and never widen the record it accepts. A tap with no such record can be one sent while a sheet the app raised on its own (an Instant reveal at the camera) was still rising, which iOS ignores: wait for the screen to be still first (`printRevealedAtTheCamera` in `PopulatedWorkflowTests`, which also touches the print's title so XCTest answers a pending Camera request before a screenshot).
- Run `sh Scripts/quiet-simulator.sh <udid>` on any simulator you create, before you boot it (it boots it; validation already does); otherwise its photo-analysis service analyzes seeded test photos at several hundred percent CPU for hours and overloads the host. In a new simulator's first minutes trustd installs any newer trust data it has just downloaded (the iOS 26.2 billing simulator's), and on CI its pinning database update held every trust check for three minutes, StoreKit's local test server included; nothing switches it off, so validation boots the billing simulator at the start of the packages part, and StoreKit tests by hand should wait out a new simulator's first minutes too (`Evidence/NativeApp/main-ci-flakes-066.md`). Shut down simulators you booted when finished.

Xcode's Dynamic Type check grows text in place and flags correctly resizing text from run to run, so no audit runs it (`auditTypes`) and `ContentSizeTests` measures every text element on the audited screens (empty Journal, catalog, Load Film, landscape Settings) at all 12 sizes instead (in light on the gate; dark gave the same results); keep that measurement in step with any new text on those screens. Scroll audited poses with held drags (`scrollUp(_:until:)` in `UITestSupport.swift`) in the left margin, never free swipes, which coast differently each run, nor right-edge drags, which can grab the scroll indicator and scrub the list (`Evidence/NativeApp/scroll-indicator-drag-053.md`), and keep the helper running the text-resizing checks (Dynamic Type, clipped text) after the others, since they move a scrolled list. `isHittable` holds while only a sliver of an element shows, and XCTest taps the middle of that sliver, which does nothing inside the home indicator's area, so scroll an element's whole frame into the window before tapping it or posing an audit: tap a scrolled-to control through `tapWhole` and pose with `scrollUpUntilWhole` (`UITestSupport.swift`), which finish in short drags, since a full drag can push other rows under the bar (a heading left half under the bottom edge is flagged for contrast in dark) (`Evidence/NativeApp/title-field-tap-054.md`, `Evidence/NativeApp/main-ci-flakes-066.md`). A tap can return before its push ends, so audit a pushed screen only after the tapped row's `waitForNonExistence` (`Evidence/NativeApp/push-audit-055.md`). The Load screen's Film title field is `FilmTitleField`, a `UITextView` whose frame is at least 44 pt tall at every size with its text where SwiftUI's field drew it and its accessibility path and focus halo on that text, clear of the heading; SwiftUI's vertical `TextField` cannot grow its frame past its text, so do not swap it back (`Evidence/NativeApp/title-field-hit-area-056.md`). Its representable, `FilmTitleTextView`, leaves the field's text alone in `updateUIView` while the field is first responder: SwiftUI can pass the title from before the latest edit, and writing that back restores a deleted character behind the cursor. UI tests that type launch with `-KeyboardAutocorrection NO`, so the field gets only the typed keys, not the autocorrection UIKit accepts when a tap focuses a pre-filled field (`Evidence/NativeApp/title-autocorrection-058.md`). `ViewThatFits` swaps view identity as text grows; prefer one custom `Layout`. `XCUIDevice.shared.appearance` did not change the app on iOS 26.5, so dark checks need a dark simulator; `Scripts/validate-local.sh` reruns only the audit suites in `dark_suites` (`Scripts/validation-parts.sh`) with the simulator set to dark. Simulator audits are not device or assistive-technology QA-13 acceptance. Diagnostic loops should exit on actual success; a maximum execution allowance does not set the default timeout. - Developed Treatments are versioned (`TreatmentVersion` in `Packages/RenderCore/Sources/RenderCore/FilmLook.swift`): a Camera package records its version (`CameraPackage.treatmentVersion`; a package locked before slice 4 has none and develops with version 2), Development assigns the Film's version to each capture, and `DevelopedTreatment` renders the assigned one. - The color stocks of the 16mm and the 6×6 develop with the captain's own files, kept unchanged in `Probes/FilmLookCalibration` as the source of truth: `FilmLook.NegativeFilm` and `ScenePasses` copy their constants, `SceneDevelopment.swift` runs their order on the scene's light, and `NegativeFilmTests`, `ScenePassesTests` and `MediumFormatPassesTests` hold the pipeline to fixtures that each `make_fixtures.py` writes from them.
