# Native Adapters

Reversible native boundaries while DEC-03 and product-flow timing remain open. The iOS-only `AVFoundationCaptureBackend` contains actual capture session and save delegates; the app's `CaptureController` (`App/Immerse/Sources/CaptureController.swift`) owns it. `Evidence/NativeCapture/2026-10-01-backend.md` at the repository root records behavior, commands and limits.

The flow coordinator first handles `CaptureStartupCoordinator.startOutcome` using its configured permission policy. Only an authorized ready plan can start the backend. Pass `TrialCoordinator.receiver(filmID:)` (from `FilmRuntime`), the only production committer, as the backend's `CaptureSaveCommitting` receiver. Keep the backend and receiver alive for all pending operations. Give each Film its own private staging directory from `FilmRepository.captureStagingDirectory(filmID:)`.

`CaptureBehavior.for(camera)` is the per-Camera capture configuration (viewfinder shape, focus setting, fixed exposure, zoom steps, flash and low-light cue); pass it in `CaptureSessionRequest.behavior`, with the 6×6 Focus slider's position in `manualLensPosition`. The Disposable's fixed exposure is applied per capture inside `capturePhoto` and released afterwards, so the viewfinder keeps metering automatically and `sceneLight` feeds its low-light cue with settled readings. `sceneLight` is one stream for the backend's life: read it from one task, because cancelling a reader ends the stream. `Evidence/NativeApp/capture-behavior-prd2-slice2.md` records the design, feasibility and what only a physical phone can prove.

Use `previewSource()` for a native preview layer. The UI must call the preview source's `update` on the main actor with the interface's orientation and `CaptureBehavior.isViewfinderMirrored`, which is true only for the front camera (preview only; saved output is never mirrored). The shooting screen holds its interface at portrait in every hold, so its preview reads upright and fills the viewfinder, as in the iPhone's Camera app, while captures follow the hold. The backend sets output orientation at each capture/clip start independently of final Movie presentation orientation. Session restart and each new recording are explicit operations.

The 6×6, Super 8 and 16mm offer the zoom steps (`ZoomStep`, `RearLensCapabilities` in `ZoomSteps.swift`) that the iPhone's rear camera reports, labeled as its Camera app labels them, plus a native sensor-crop step for any lens only where the camera reports it, labeled by the factor it shows (`secondaryNativeResolutionZoomFactors` of that lens's active format, read once the session runs on its format, so `start` and `switchLens` read it again; a lens that is not the session's input then reports the format it has). The lens list and factors come from the rear virtual device, which is only read: `AVFoundationCaptureDeviceDiscoverer.rearLenses()` multiplies its switch-over zoom factors by `displayVideoZoomFactorMultiplier`. `selectZoomStep` runs the step on the matching physical lens as the session's input, swapped as a front/rear switch is, so focus, exposure and `NativeCameraControls.manualFocus` describe that lens, and the person's Focus position and exposure bias go with them to it, the bias within that lens's range (`CaptureBehavior.lensExposureBias`). On a movie Camera every step records the wide lens's 4:3 movie size at 30 frames per second: a lens without a format of that size and rate is not offered (`MovieCaptureFormat.lensesRecordingTheWideLensFormat`), and a step's lens is given exactly that format (`MovieCaptureFormat.matching`); a step is available only between Recorded Clips; photo steps are available only between exposures. Once a lens is the input it runs on the format the session gives it, so the lenses are read again, and a crop that format does not report is refused: the camera returns to the step it was on, and the read leaves the crop out of the steps offered. The bias goes with the person on a zoom step only; a front/rear switch leaves each camera on its own. A step is refused unless `CaptureSessionPlan.zoomDecision` allows it (rear only, between captures, a step the iPhone reports). Every lens is returned to its own zoom factor when a session starts or switches, so no Camera opens zoomed. `Evidence/NativeApp/capture-sideways-zoom-068.md` records the design and what only a phone can show.

Movie sessions record the largest native 4:3 format no larger than 1920x1080 at 30 frames per second (`MovieCaptureFormat`), so a portrait clip is 3:4 and fills a portrait Movie. That size is provisional pending DEC-04. New Super 8 and 16mm packages record that a Film may carry Live Audio; the app asks for microphone access only when one of those shooting screens opens (`CaptureController`), and the backend attaches the authorized microphone only while a clip records, in stereo where the phone can and AAC at 48 kHz where the output lets it be set, starting the clip once the microphone's connection is live and letting it go when the clip ends, so permission is read again for each clip and a change in Settings affects the next recording. Older stored packages remain silent and never prompt. `startMovie` takes the Film's remaining whole frames (`Film.remainingMovieFrames`), caps the recording at exactly that duration, and accepts a clip whose picture, its video track, lasts at most those frames: its sound can end a packet later. It also writes the lens's white-balance reading at the clip's start into the clip as QuickTime metadata (`SceneWhiteBalance` in `FilmDomain`), which the 16mm color Film Stock's fixed daylight balance develops against; the viewfinder and the recording keep the phone's automatic white balance, and a reading the lens cannot convert is left out.

`capturePhoto` and `startMovie` enqueue native work. The backend's events stream reports a saved event only after the receiver acknowledges durable persistence. A failed persistence attempt retains the staged file and keeps capture/lens switches blocked; use `retryPendingSave` for that same file. `suspend`/`shutdown` never intentionally discard pending files. `retainedCommittedFiles` reports files that committed but whose staging-file removal failed.

Run `swift test --package-path Packages/NativeAdapters` for coordinator and synthetic native-file tests. Compile both iOS destinations using the commands in the evidence report, because macOS tests exclude the iOS-only capture implementation. Do not install this backend or its compile probe under the separate Keychain-probe device approval.
